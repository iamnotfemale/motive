## 2. 제품 개요와 P0 범위

막연한 아이디어를 근거·검토 질문으로 발전시키고, 선택한 해결책과 요구사항을 개발 에이전트용 Markdown으로 넘기는 **캔버스형 워크스페이스**. 주 사용자는 해커톤·공모전·팀플을 하는 대학생. 1인 로컬 우선.

P0 포함: 문제 입력 → 첫 캔버스 → 의미 카드 편집 → 자료 드롭·근거 승인 → 원문/해석 구분 → Markdown 편집 → 결정·요구사항 → 미확인 상태를 남기는 MD 인계.
P0 제외(화면에도 없음): 로그인·결제·팀원 초대·실시간 커서·음성·OCR·웹 검색·자동 배포·에이전트 실행·시장 검증 점수·Codex/Claude Code 버튼·ZIP 목록.

정보 구조에서 NOTT와 다른 점: 문서 트리 대신 48px 도구 레일 / 긴 문서 카드 대신 288px 의미 카드 / 색 섹션 대신 선·유형 배지·관계 라벨 / 상시 AI 채팅 대신 선택 대상의 액션·검토 패널(보조 패널은 한 번에 하나만).

## 3. 화면 목록: S01–S08

프로토타입 바의 화면 칩은 각 화면의 **프리셋 상태**로 이동한다. 실제 제품에는 프로토타입 바가 없다. 화면 ID는 `data-screen-label`로 프레임에 노출된다.

### S01_problem-start · 문제 작성
- 목적: 가입·폴더·태그 없이 문제 문서를 적는다.
- 시작 상태: 빈 상태. 720px 작성 영역, 질문 `어떤 문제를 풀고 있나요?`, 보조 문구, 제목(선택)·본문·`프로젝트 시작`. 예시는 입력 아래 별도 캡션 + `예시 넣기` 버튼(플레이스홀더와 혼동 방지). `최근 프로젝트 ▾`는 헤더 우측 링크만.
- 버튼별 행동
  - `프로젝트 시작`: 본문 공백 → 오류 상태(경계 danger, 문구 `문제를 한 줄이라도 적어주세요…`), 본문 재입력 시 오류 해제. 정상 → `시작하는 중…`(버튼 disabled, 스피너, 문구 `저장하고 캔버스를 준비하는 중…`) → 약 700ms 후 S02. AI 분석 대기 없음.
  - 저장 실패(S08 `s01Fail`): 문구 `저장하지 못했어요. 작성 내용은 이 화면에 그대로 있어요.`, 버튼 `다시 시도` + `작성 내용 복사`. 입력은 유지.
- 상태 5종: 빈 상태 / 작성 중(글자 수·`저장 전`) / 입력 없음 오류 / 시작·저장 중 / 저장 실패.

### S02_first-canvas · 첫 캔버스
- 시작 상태: S01 본문이 `P-01` 문제 카드 제목이 되어 캔버스(72,48)에 나타남(cardIn 200ms, 이후 위치 재조정 없음). 카드 오른쪽에 `다음으로 이어가기` + `가설 추가 / 자료로 근거 찾기 / 검토 질문 추가` 점선 버튼 3개. 나머지는 빈 공간. 단계 강조 `정의`.
- 행동: `가설 추가` → H-01 생성·선택, P-01→H-01 `이 문제에서 출발` 관계. `자료로 근거 찾기` → 자료 첨부 팝오버(S04). `검토 질문 추가` → C-01 생성. 제안 3개는 노드가 2개 이상이거나 패널이 열리면 사라짐.
- `문제 다듬기`(P-01 hover/선택 액션) → 우측 400px 비교 패널: 원문 / AI 제안(미확정 배지) / `원문 유지` `제안 적용`. 키 없음 변형에서는 AI 제안 대신 안내 문구, `제안 적용` disabled.

### S03_reasoning-canvas · 추론 캔버스
- 시작 상태: 공통 예시 10개 노드(P-01, H-01, C-01, E-01, E-02, S-01, S-02, D-01, R-01, R-02)와 관계 9개. H-01 선택.
- 카드 상태: 기본(border #E5E7EB) / hover(border #98A2B3, 그림자, ⋯ 표시, 하단 액션 팝오버) / 선택(border accent + 3px accent-subtle ring) / 키보드 focus(2px accent outline, offset 2) / 다중 선택(Shift+클릭, 액션 팝오버 숨김) / 관계 선택(선·라벨 accent, 라벨 아래 팝오버 `A → B · 관계명 · 관계 변경 ▾`).
- 노드 액션(hover 또는 단일 선택 시, 패널 닫힘 상태에서만): 문제 `문제 다듬기·가설 추가` / 가설 `근거 연결·검토 질문 만들기` / 근거 `원문 보기·다른 주장에 연결` / 검토 질문 `상태 변경·연결 보기` / 해결안 `결정 만들기·근거 연결` / 결정 `요구사항 추가·인계에 포함` / 요구사항 `수용 기준 편집·범위 변경` + 공통 `열기`.
- 열기 경로: 더블클릭 / ⋯ / `열기` / Enter(focus 상태) / ⌘K `상세 열기`. 우클릭 전용 기능 없음.
- 캔버스 조작: 빈 곳 드래그 = 이동(패닝), 카드 드래그 = 위치 이동(즉시 추종). 빈 곳 클릭 = 선택 해제 + Inspector/다듬기 패널 닫기(자료함·검토·결정 패널은 유지). 도크 `− 100% +`, `⛶ 화면 맞춤`(최소 0.5, 0.7 미만이면 100% 복귀 안내 토스트), `정리`(기본 배치 복원).
- 헤더 `인계 전 확인 N개`는 실제 미확인 항목 수(§8). 신뢰도·완료율 없음.

### S04_source-review · 자료 검토 (대표 인터랙션)
- 진입: 도크 `자료 첨부` / 레일 / 제안 / 가설 `근거 연결` / ⌘K. 팝오버에서 데모 파일 선택(`interview-demo.md` 합성 자료, `submission-guide-demo.pdf` 가상 안내) → 파일 고스트가 포인터를 따름(모의 드래그).
- 8단계(패널 상단 스텝 인디케이터로 현재 단계 표시)
  1. 끌어오기 — 고스트 + 힌트 `카드 위에 놓으면 첨부 · 빈 곳은 자료함에 추가`
  2. 드롭 영역 — 카드 위: 2px accent outline + `이 가설에 자료 첨부`(유형별 문구). 카드 클릭 또는 Enter로 드롭.
  3. 파일 저장·읽기 — 우측 440px 검토 패널, `자료 읽는 중` indeterminate 바, `파일 저장됨`. (PDF는 텍스트 없음 → 자료함 + 경고로 분기)
  4. AI 전송 동의 — `근거 후보를 찾을까요?` `첨부만 유지` / `동의하고 후보 찾기`. 키 없음이면 후보 찾기 disabled + 안내.
  5. 후보 표시 — 캔버스에 점선 고스트 카드(`AI 제안 · 미확정`) + 점선 관계. 패널에 후보 카드 2개.
  6. 원문·해석 검토 — 후보 카드: `interview-demo.md · 줄 N`, 인용 블록(라벨 `원문 인용`), `해석 · AI 작성` 2줄(주장 + 한계), 연결 대상, 관계 select(지지/반대 근거/제안의 근거/관련). `원문 보기` → 같은 패널에서 원문 줄 보기(강조 줄, 뒤로 가기).
  7. 선택 승인 — `제외`(되돌리기 가능) / `근거로 추가`. 점선 카드·점선 관계 클릭은 승인되지 않음(토스트 안내).
  8. 실선 관계 — 승인한 후보만 E-0x 실선 카드 + 실선 관계, 토스트 `E-02 근거로 추가했어요 · 반대 근거 관계 생성`, 저장 상태 `저장 중… → 저장됨`.
- 빈 캔버스에 드롭: `자료함에 추가했어요` + 연결 대상 목록 → 선택 후 4단계로.
- 첨부만 유지: `원문 열기`로 줄을 눌러 직접 근거 선택 → `근거로 추가`.
- 후보 0개: `관련 근거를 찾지 못했어요. 원문에서 직접 선택할 수 있어요.` + 버튼(오류 스타일 아님).

### S05_node-detail · 상세 / Markdown
- 진입: 열기 경로. 우측 400px(1280에서 360) 비모달 Inspector, 카드 선택 유지. 헤더: 유형·ID·`넓게 보기`·닫기(Esc). 제목 textarea(카드 제목과 동기). 탭 `내용 / 연결 / 출처`.
- `내용` — `작성 / Markdown` 세그먼트.
  - 작성: 서식 툴바 `H(섹션 추가) • ❝ ☑ ↗ </>`. 본문은 `##` 섹션을 유형별 필드로 렌더: 텍스트 섹션(textarea, focus 시 배경), 인용 섹션(따옴표 블록), 목록 섹션(불릿/체크박스 행 + `항목 추가`). 가설: 본문·검증 계획·결과 기록·검토 상태 / 근거: 원문 인용·출처·해석·한계 / 요구사항: 사용자 행동·수용 기준·범위·연결된 결정. 표·HTML 감지 시 `지원하지 않는 문법… Markdown 탭에서 편집` 안내(원문 보존).
  - Markdown: monospace textarea. 첫 `# ` 줄 = 카드 제목, `## ` = 작성 모드 섹션. 편집 즉시 카드에 반영(양방향, 단일 소스 = 노드 md 문자열). 별도 문서 생성·목록 추가 없음.
- `연결`: 관계 목록(`A → B`, 상대 제목, 관계명, 반대 근거는 danger 점) 클릭 시 해당 노드 선택. `출처`: 파일·줄·`합성 자료`·`원문에서 인용 확인됨`·`원문 보기`; 원본 없음이면 danger 문구 + `자료 다시 연결 / 인계에서 상태 표시`.
- 푸터: 저장 상태(저장 중… / 저장됨 · 다른 카드로 이동해도 입력은 유지돼요 / 실패 + `재시도` `작성 내용 복사`). 다른 노드 클릭 시 Inspector는 그 노드로 전환, 이전 입력은 저장됨.

### S06_decision-scope · 결정과 범위
- 진입: S-01 `결정 만들기` / 단계 `결정`. 우측 400px 결정 패널, 배지 `초안`.
- 내용: 선택한 해결안 S-01(채택) / 결정 이유 textarea / 기각 대안 S-02(`기각 | 보류` select) / 열린 질문·위험 인지: C-01 체크 `미검증이지만 이번 MVP에서 시도 — H-01이 검증된 것은 아니에요` + 새 열린 질문 입력.
- `결정 확정`(명시적): D-01 카드 생성, D-01→S-01 `채택`, D-01→S-02 `보류·기각` 실선, S-01/S-02 상태 갱신, 배지 `확정`, 필드 읽기 전용, 토스트.
- 확정 후 요구사항 섹션: `사용자가 무엇을 할 수 있어야 하나요?` / `완료됐다고 판단할 기준은 무엇인가요?`(줄마다 기준) → `요구사항 추가` → R-01, R-02 생성 + D-01→R `구현 범위` 관계. 각 요구사항 `이번 MVP에 포함 / 보류 / 제외` select. 안내 `요구사항이 생겨도 시장 검증이나 개발 완료를 뜻하지 않아요.` 푸터 `인계에 포함` → S07.
- 후속 변경(S08 `postChange`): 상단 `결정 이후 관련 정보 1건이 바뀌었어요` → `바뀐 근거 확인`(E-02 해석 이전/이후) → `검토했어요`. 결정은 유지. "AI가 틀렸다" 같은 단정 없음.

### S07_build-handoff · 개발 인계
- 진입: 헤더 `개발 인계` / 단계 `인계` / D-01 `인계에 포함`. 캔버스를 대체(헤더 유지, `캔버스로 돌아가기`).
- 좌 300px(1280: 272): `시스템 확인`(문제·대상 / 선택한 해결안 / 출처 유효성 — 자동, ✓ 또는 !) + `내가 확인할 항목`(수용 기준 / 열린 질문 인지 / 변경 검토 / 제외 범위 — 체크박스 버튼). 헤더 문구: 남은 항목 있으면 `남은 확인 N개 · 확인 없이도 초안으로 내보낼 수 있어요`, 모두 끝나면 **`인계에 필요한 정보를 확인했어요`**.
- 우: `PROJECT_HANDOFF.md` `미리보기 / 원문` 토글. 내용은 현재 캔버스 상태에서 생성: 1 문제 · 2 선택한 해결안 · 3 요구사항(수용 기준·범위) · 4 결정 이유 · **5 반대 근거** · 6 미검증 가설(열린 질문 포함) · 7 제외 범위 · 8 출처 · 말미 `미확인 항목은 그대로 남겼습니다`. 없는 항목은 `(아직 없음)`.
- 버튼: `Markdown 복사` / 점검 완료 시 `파일 다운로드`(ink 버튼), 미완료 시 `초안으로 다운로드`(outline). 다운로드 후 `다시 다운로드`.
- 상태: 캔버스 변경 후 `미리보기가 오래됐어요 · 새로 만들기`(문서 60% 불투명) / 다운로드 완료 토스트 / 복사 실패 토스트 + `원문 보기` 액션.

## 7. 근거 검토와 Markdown 편집의 상세 행동

근거 검토
- 드롭 ≠ 근거. 드롭은 Source 저장만. 후보는 동의 후 생성되며 `pending → approved | excluded`. 승인 시에만 Evidence 노드 + 실선 관계. 후보 관계 select는 승인 전만 변경 가능.
- 후보 카드 정보: 파일·줄(실제 원문 줄), 인용(원문 그대로, `원문 인용` 라벨), 해석 2줄(`AI 작성` 라벨: 주장 / 한계), 연결 대상, 관계.
- 원문 보기는 같은 패널 내부 뷰(원문 라이브러리 이동 없음). 강조 줄 = 후보 줄. 아무 줄이나 눌러 직접 선택 → `근거로 추가`.
- 인용 미일치는 승인 불가, 원문 확인 또는 제외만. 후보 오래됨은 다시 확인/재분석.

Markdown 편집
- 노드 본문은 하나의 md 문자열. `# 제목` 1개 + `## 섹션` n개.
- 작성 모드는 섹션을 필드로 렌더하고 편집 결과를 다시 md로 직렬화(`- ` 목록, `- [ ] `/`- [x] ` 체크, `> ` 인용). 툴바 삽입은 마지막 focus 섹션 끝에 새 줄로 추가; focus 없으면 안내 토스트.
- Markdown 모드 변경은 즉시 카드 제목·작성 모드에 반영. 표·HTML 등 미지원 문법은 그대로 보존하고 안내만.
- 자동 저장: 변경 → `저장 중…`(500ms) → `저장됨`/`저장 실패`. 실패 시 입력 유지·재시도·복사.
